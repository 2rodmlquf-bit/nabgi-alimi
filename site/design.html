납기 알리미소개화면만든 과정설계와 확인직접 써 보기

설계와 확인

AI와 일한 방식, 클라우드 저장 설계, 확인한 것과 못 한 것을 적었습니다.

AI와 일하는 방식 (하네스)

코딩 AI에게 "알아서 해 줘"라고 하지 않고, 일하는 순서와 규칙을 파일로 정해 두고 시켰습니다. 문서가 먼저, 코드는 그다음입니다.

문서 먼저

문제 정의 → 화면 구조(IA) → 사용자 여정 → PRD → ERD → spec·plan → Intent 순서로 한 문서씩 승인한 뒤 개발합니다. 끝나면 문서를 갱신합니다.

인터뷰로 결정

애매한 것은 AI가 추측하지 않고 한 번에 하나씩 물어서 정합니다. 용어는 용어집에, 되돌리기 어려운 결정은 ADR(결정 기록) 8건에 남겼습니다.

코드 규칙

파일 500줄·함수 40줄 상한, 안쪽 업무 규칙이 바깥 화면·DB를 가져다 쓰지 않는 방향 규칙, 판정·계산은 단위 시험 필수.

자율성의 선

파일 수정·시험·로컬 커밋은 알아서, push·배포·삭제·서비스 쓰기·결제는 반드시 멈추고 묻게 했습니다. 무료 플랜만, 가상 데이터만 씁니다.

QA는 둘로 나눔

AI가 직접 실행한 QA(Pass/Fail/No Run과 증거)와, 사람이 눈으로 봐야 하는 QA(글이 읽기 편한지, 실제 설치 등)를 시트에 따로 등록합니다. 증거 없는 Pass는 쓰지 않습니다.

찾은 문제도 기록

시험이 통과해도 화면을 열어 확인했고, 그렇게 찾은 문제(예: 2열 배치가 안내 문구를 쪼개던 것)는 고친 뒤 시험에 반영했습니다.

클라우드 저장은 이렇게 설계했습니다

이 컴퓨터가 기준

기록은 항상 로컬에 먼저 저장합니다. 인터넷이 끊겨도 기록이 막히지 않고, 돌아오면 이어서 올립니다.

올린 장부와 비교

따로 쌓아 둔 대기열 대신 "올린 것의 장부"와 지금 상태를 비교합니다. 앱을 꺼도, 같은 일을 다시 해도 결과가 같습니다.

기록은 지우지 않음

서버에서도 기록은 쌓기만 하고 "삭제 표시"만 붙입니다. 본인 행만 보이도록 보안 규칙(RLS)을 걸었습니다.

계정에 묶음

이 컴퓨터의 기록은 처음 로그인한 계정에 묶여 다른 계정은 거부됩니다. 비밀번호는 저장하지 않습니다.

얼마나 확인했나요

386단위 시험
19화면 시나리오(E2E)
66DB 규칙 시험
0보안 점검 문제 (Supabase)

시험이 통과해도 믿지 않고 실제 화면을 열어 확인했고, 그렇게 찾은 문제들은 BACKLOG에 기록했습니다.

아직 못 한 것 (솔직하게)

가상 데이터로만 검증했습니다. 실제 회사 파일에서 열 이름·주문번호 유일성 가정이 맞는지, 깨끗한 PC에서 설치·업그레이드·삭제가 되는지, 스크린리더로 직접 써 보는 것은 아직 확인하지 못했습니다. 설치 파일은 서명되지 않았습니다.
