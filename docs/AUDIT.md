## 3. 발견 사항 (GAP)과 처리

### GAP-1. '확인 필요' 주문이 예외 목록 표에 나오지 않았다 (FR-01 (c)) → **해결 (G-8, A안)**

- **감사 때 현상**: 샘플에서 납기일을 읽을 수 없는 주문 2건(`PO-2026-1037`, `PO-2026-1038`)이 **카드와 알림 줄**에만 나왔다. 표에는 없어서 상세를 보거나 안내를 기록할 수 없었다.
- **문서와의 차이**: README는 "숨기지 않고 보여 줌", PRD는 "'확인 필요'로 남는다", IA의 예외 목록은 "지연·임박 주문"이라 해석이 갈렸다.
- **결정**: 2026-10-19 사용자가 **A안**을 선택했다. 납기를 모르는 주문이 가장 놓치기 쉬워서, "알아채는 순간"(CUJ-1)을 푸는 도구가 표에서 빼면 취지에 어긋난다.

| 바뀐 것 | 내용 |
|---|---|
| 표 | '확인 필요' 주문이 지연·임박 행 **뒤(맨 아래)**에 나온다. 배지 글자는 "확인 필요", 남은 일수는 "-". 샘플은 13행 → **15행** |
| 안내 기록 | 상태 값 `확인필요`를 새로 받는다. 예전 코드는 지연이 아니면 모두 "임박"으로 기록해 잘못 남을 뻔했다 |
| 다시 안내 규칙 | ① 납기를 모른다고 안내한 뒤 **납기가 확인되면** 다시 안내 ② 계속 모르는 채 **7일 넘게** 소식이 없으면 다시 안내(가정) ③ 파일에 적힌 값이 바뀌면 다시 안내 |
| 현황 막대·보고서 | 확인 필요까지 센다. 필터 칩은 "임박"과 섞지 않고 "확인 필요 N건"을 따로 보여 준다. 지연 전에 먼저 안내한 건(선제 안내)은 임박뿐 아니라 확인 필요 단계의 안내도 센다 |
| 안내문 | 납기일을 읽을 수 없으면 "기존 납기일은 입니다" 같은 빈 문장 대신 "납기일을 아직 확인하지 못했습니다"라고 쓴다 (파일에 적힌 값이 있으면 괄호로 보여 주되 날짜로 지어내지 않는다). 기본 템플릿은 사과형 대신 공지형 |
| 한 통 안내문 | "■ 납기 확인 중 N건" 구간을 따로 둔다 |
| 예외 목록 CSV | 확인 필요 줄에도 "연구원 안내" 상태가 들어간다 (예전에는 빈 칸) |

- **확인**: 단위 `test/needCheck.test.js` 12개, E2E `A-05` 16건. 기존 테스트 중 **한 개**(`informedReport.test.js`의 "확인 필요 줄은 비어 있다")는 예전 결정을 고정해 둔 것이라 새 결정에 맞춰 고쳤다. 나머지 기존 테스트는 그대로 통과한다. 행 수 기대값(13 → 15)이 걸린 E2E 몇 곳도 고쳤다.
- **남은 가정**: 확인 필요 주문의 "7일" 기준은 지연과 같게 둔 가정이다. 실제로 맞는지는 입사 후 확인한다.

## 5. 용어 점검 (T1.6)

| 항목 | 결과 |
|---|---|
| "재안내" vs "다시 안내" | **화면 문구는 이미 "다시 안내"로 통일**되어 있다. "재안내"는 내부 상태 값 `재안내필요`(10곳)에만 남아 있다. 사용자에게 보이지 않으므로 바꾸지 않는다. IA 5절의 우려(L-11 일부)는 해소됨 |
| "요청자" vs "연구원" | **섞여 있다.** 표 열 머리글, 필터 칩("요청자 …"), "(요청자 없음)", 열 매핑 안내는 "요청자", 그 밖(안내문·분석·막대 등 27곳)은 "연구원". `DECISIONS.md` G-3 잠정안(표 열은 요청자, 화면 문구는 연구원)에 따르면 **필터 칩 문구만 고칠 대상**이다 → Phase 6 |
| "안내"(연구원) vs "연락"(공급사) | 대체로 지켜진다. `escalate.js`의 "영향받는 연구원에…" 문구 한 줄은 연락과 안내가 섞였는지 Phase 6에서 확인 |
