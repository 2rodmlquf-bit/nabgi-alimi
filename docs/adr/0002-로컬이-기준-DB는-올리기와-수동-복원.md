# ADR-0002: 로컬이 화면의 기준이고, DB는 "올리기 + 수동 복원"만 한다

- 날짜: 2026-10-20
- 상태: 결정됨

## 결정
화면이 읽고 쓰는 기준은 항상 로컬 저장소다. 변경은 로컬에 먼저 쓰고, 대기열(outbox)에서 DB로 올린다. DB에서 로컬로는 사용자가 **복원 버튼**을 누를 때만 내려받는다. 시작할 때마다 자동으로 병합하지 않는다(다기기 동기화는 이번 범위가 아니다).

## 왜 되돌리기 어려운가 / 왜 의외인가
- "DB가 기준"이 아니라서, DB에 있는 것과 로컬에 있는 것이 어긋날 수 있고 그 책임을 앱이 진다(대기열, 재시도, 상태 표시, 복원 규칙).
- 나중에 다기기 병합으로 가려면 DB→로컬 병합 규칙이 새로 필요하다. 이 결정은 그것을 하지 않는다는 선택이다.

## 대안과 버린 이유
- DB가 기준(온라인에서만 기록): 안내 기록이 안 눌리면 추적이 무너진다는 이 앱의 가장 큰 위험을 키운다.
- 항상 양방향 병합: 충돌 규칙이 필요해 G-6에서 뺀 다기기 범위가 된다.
- 올리기만(복원 없음): 로컬 파일을 잃으면 DB가 있어도 쓸모가 적다.

## 결과
- 올리기는 id 기준 업서트(멱등). 같은 기록을 두 번 올려도 한 건이다.
- 복원은 사용자가 누를 때만, 로컬에 이미 있는 기록은 id로 건너뛴다.
