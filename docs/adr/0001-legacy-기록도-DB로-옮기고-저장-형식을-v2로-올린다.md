# ADR-0001: 공급사 연락·대체품·분납 기록(legacy)도 DB로 옮기고, 저장 형식을 v2로 올린다

- 날짜: 2026-10-20
- 상태: 결정됨 (G-6의 "legacy는 로컬에 남김"을 **바꾼다**)

## 결정
공급사 연락 기록, 연락함 표시, 대체품 확인, 분납 일정도 데이터베이스로 옮긴다. 이를 위해 로컬 저장 형식을 v1에서 v2로 올려, 이 기록들도 안내 기록처럼 **고유 id·만든 시각·삭제 표시**를 갖게 한다(쌓기만 하고 고치지 않는다).

## 왜 되돌리기 어려운가 / 왜 의외인가
- v1의 legacy는 id도 시각도 없고 통째로 덮어쓰는 구조다(분납 일정은 목록 전체를 교체). 그대로는 올리기를 멱등으로 할 수 없다. 형식을 바꾸면 이전 코드(`persist.js`, `store/core.js`)와 화면의 저장 호출까지 고쳐야 하고, 한번 DB에 id가 들어가면 되돌릴 수 없다.
- G-6(2026-10-19)은 "legacy는 로컬에 남긴다"였다. 이번 인터뷰에서 사용자가 "데이터베이스로 옮긴다"가 반쪽이 되는 것을 원하지 않아 뒤집었다.

## 대안과 버린 이유
- 로컬에 남기는 혼합 저장소(G-6): 다른 PC에서 안 보이고, "옮겼다"가 반쪽이다.
- 현재 상태를 통째로 덮어쓰기: 오프라인 대기열과 맞지 않고 이력이 사라진다.
- 연락 이력만 id 방식: 일관성이 없다.

## 결과
- `DATA_MODEL.md`를 v2로 고치고, v1 → v2 이전 함수(기존 legacy에 id·시각 채우기)를 만든다. 이전 전 백업.
- 화면 동작은 바뀌지 않아야 한다(저장소만 바뀐다).
