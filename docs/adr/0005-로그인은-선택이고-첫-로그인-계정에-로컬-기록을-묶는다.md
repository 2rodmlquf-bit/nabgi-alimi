# ADR-0005: 로그인은 선택이고, 첫 로그인 계정에 로컬 기록을 묶는다

- 날짜: 2026-10-20
- 상태: 결정됨

## 결정
- 로그인 방식은 **이메일 + 비밀번호**다.
- **공개 가입은 닫는다.** 계정은 사용자가 Supabase 화면에서 직접 하나 만든다. 앱에 가입 화면과 비밀번호 재설정 기능을 두지 않는다(비밀번호 변경도 Supabase 화면에서 한다).
- 로그인은 **클라우드 저장을 켤 때만** 한다. 로그인하지 않아도 앱의 모든 기능이 그대로 동작한다.
- 세션은 OS 보안 저장소로 암호화해 저장하고 로그아웃할 때까지 자동으로 유지한다. 보안 저장소를 쓸 수 없는 PC에서는 앱을 켜 둔 동안만 유지한다(기존 API 키 방식과 같다).
- **첫 로그인에 성공한 계정이 이 PC 로컬 기록의 주인 계정이 되고, 다른 계정으로는 로그인할 수 없다.** 주인 계정은 로컬 파일의 `cloudLink`에 둔다.
- 로그아웃하면 세션만 지운다. 로컬 기록과 못 올린 대기열은 그대로 두고 올리기만 멈춘다.
- 로그인 관련 정보를 담는 표를 데이터베이스에 따로 만들지 않는다(Supabase의 `auth.users`만 쓴다).

## 왜 되돌리기 어려운가 / 왜 의외인가
- 로컬 기록에는 계정 정보가 없다(ADR-0002: 로컬이 기준). 아무 계정으로나 로그인하게 두면 그 PC의 기록이 로그인한 계정 아래로 올라가므로, 계정을 잘못 쓰면 **남의 계정에 기록이 섞인 채 DB에 쌓이고** 되돌리기 어렵다. 그래서 주인 계정 고정이 필요하다. 그 대가로 계정을 바꾸고 싶을 때 쓸 수 있는 정식 방법이 아직 없다(열린 질문).
- "공개 가입을 닫는다"는 앱에 들어 있는 공개 키만으로 누구나 계정을 만들 수 없게 하려는 선택이다. 그 대가로 사용자를 늘리려면(팀 사용) 로그인 설계를 다시 열어야 한다.
- 비밀번호 재설정 메일 링크는 데스크톱 앱으로 돌아오는 설정이 필요할 수 있어 앱에 넣지 않았다. 사용자가 프로젝트 관리자라서 가능한 선택이다.

## 대안과 버린 이유
- 이메일 링크(매직 링크)·6자리 코드: 비밀번호 관리는 없지만 매번 메일을 확인해야 하고, 링크 방식은 앱으로 돌아오는 설정이 추가로 필요하다.
- 앱 안의 가입 화면: 공개 가입을 열어야 해서 계정이 늘어날 수 있다.
- 앱을 켤 때마다 로그인: 로컬이 기준이라는 설계와 부딪히고, 로그인 실패가 일상 작업을 막을 수 있다.
- 로그아웃 때 대기열 삭제: 올리지 못한 변경이 사라져 DB와 로컬이 어긋날 수 있다.

## 결과
- DB에는 로그인용 표를 더하지 않는다. 로컬 파일에 `cloudLink`(주인 계정 등), OS 보안 저장소에 세션을 둔다(`docs/erd.md`).
- DB 행의 `user_id`는 앱이 넣지 않고 DB가 로그인한 사용자로 채운다(`default auth.uid()`). 앱은 올리기 전에 로그인한 계정이 주인 계정과 같은지 확인한다.
- Supabase의 로그인 시도 제한·세션 수명·비밀번호 정책은 확인하지 않았다. 착수 때 공식 문서로 확인한다.
