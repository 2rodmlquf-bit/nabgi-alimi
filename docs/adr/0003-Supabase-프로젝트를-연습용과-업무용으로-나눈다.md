# ADR-0003: Supabase 프로젝트를 연습용과 업무용 두 개로 나눈다

- 날짜: 2026-10-20
- 상태: 결정됨 (업무용은 보안 승인 뒤에 만든다)

## 결정
- **연습용 프로젝트**: 가상·연습 데이터만. 지금 만든다.
- **업무용 프로젝트**: 회사 데이터는 회사 정보보안 승인을 받은 뒤에만, 별도 프로젝트에 담는다. 승인이 없으면 회사 데이터는 로컬 전용을 유지한다.
- 스키마는 같은 마이그레이션 파일을 두 프로젝트에 똑같이 적용한다. 보안은 지금은 "본인 행만 접근(RLS)"과 "service_role 키를 앱·저장소에 넣지 않기"만 한다.

## 왜 되돌리기 어려운가 / 왜 의외인가
- 연습 데이터와 회사 데이터가 한 프로젝트에 섞이면, 회사 데이터가 개인 계정에 들어간 것이 되어 나중에 분리·삭제가 어렵다.
- "회사 데이터를 담을 수 있게 미리 설계"라고 했지만 지금 스키마에는 추가 보안(암호화, 보존기간)을 넣지 않기로 했다. 그것은 승인 절차와 함께 업무용 프로젝트에서 따로 정한다.

## 대안과 버린 이유
- 한 프로젝트에 섞어 쓰기: 위의 문제.
- 지금 결정하지 않기: 앱의 설정(어느 프로젝트에 연결하는지)이 나중에 바뀌면 이전 비용이 생긴다.

## 결과
- 앱 설정에 "어느 프로젝트에 연결하는가"가 들어간다(프로젝트 주소와 공개 키는 코드가 아닌 설정으로 받는다).
- 자유 입력 글(안내 메모, 빠른 메모, 연락 기록 메모)에 이름·일정이 적힐 수 있다는 점은 업무용 프로젝트 승인 때 다시 다룬다.
