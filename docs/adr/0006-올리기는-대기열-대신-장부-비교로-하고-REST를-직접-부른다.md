# ADR-0006: 올리기는 "쌓아 둔 대기열" 대신 "장부 비교"로 하고, Supabase는 REST로 직접 부른다

- 날짜: 2026-10-20
- 상태: 결정됨, 구현·시험 완료 (`src/sync/`)

## 결정
1. **대기열을 따로 쌓지 않는다.** 지금 로컬 상태에서 DB 행을 계산하고, 지난번에 올린 행의 지문(장부 `cloud.json`의 `ledger`)과 비교해 "아직 못 올린 것"을 구한다. (ADR-0002의 "대기열"을 이렇게 구현한다. 사용자에게는 "올릴 기록 N건 대기"로 보인다.)
2. **Supabase 라이브러리 없이 공식 REST 주소(`/auth/v1`, `/rest/v1`)를 `fetch`로 직접 부른다.** 필요한 호출이 로그인·갱신·읽기·넣기·수정 몇 개뿐이다.
3. **복원은 "로컬에 없는 id만 더하고, 현재 값은 `updatedAt`이 새로운 쪽이 이긴다."** 단, 기본값뿐인 로컬 설정(처음 켠 앱)은 서버의 직접 바꾼 설정을 이기지 못한다.

## 왜
- 쌓는 대기열 파일은 버그로 한 건이 빠지면 영영 어긋난다. 장부 비교는 상태가 기준이라 빠진 것이 다음 올리기에 저절로 잡히고, 앱을 꺼도·같은 일을 다시 해도 결과가 같다(멱등). 이전(처음 한 번)도 "장부가 빈 상태의 올리기"와 같아서 코드가 하나다.
- 라이브러리를 쓰지 않으면 의존성이 늘지 않고, 시험에서 가짜 서버로 바꾸기 쉽다.

## 대가·한계
- 기록이 많아지면 매번 전체를 계산한다(주문당 한도가 있어 2MB 이내라 문제 없음).
- 쌓는 기록은 "다른 열이 바뀌는 일"이 없다는 전제다(삭제 표시만 바뀜). 이 전제는 DB가 열 단위 권한으로 강제한다.
- 서버가 거부하는 행(값 규칙 위반)은 한 건씩 보내 가려내고, 나머지는 올린다. 거부된 행은 대기로 남고 이유를 화면에 보여 준다.
- 로그인 토큰은 OS 보안 저장소로 암호화해 파일에 두고(암호화를 못 쓰면 메모리에만), 비밀번호는 저장하지 않는다.
- 다기기 병합은 여전히 범위 밖이다.
