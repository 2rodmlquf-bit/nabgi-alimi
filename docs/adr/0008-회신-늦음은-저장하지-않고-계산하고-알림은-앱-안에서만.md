# ADR-0008: "회신 늦음"은 저장하지 않고 계산하며, 알림은 앱 안에서만 한다

- 날짜: 2026-10-20
- 상태: **계획 결정** (기획 단계)

## 결정
- 회신 늦음은 **저장하는 상태가 아니다.** 지금의 기록과 기준일로 매번 계산한다: 주문의 가장 최근 회신의 약속일이 기준일보다 지났고, 그 뒤 새 회신이 없고, 입고 완료가 아니면 "회신 늦음".
- 알림은 **앱 안**(홈 탭, 예외 목록 표시)에서만 한다. Windows 알림은 만들지 않는다.

## 왜 되돌리기 어려운가 / 왜 의외인가
- 상태를 DB·파일에 저장하는 쪽이 조회는 쉬워 보이지만, 기준일(샘플은 10/12처럼 바뀐다)과 기록이 바뀔 때마다 저장된 상태가 어긋난다. 한 번 저장하기 시작하면 정정·이전 규칙이 따라온다.
- Windows 알림은 앱이 계속 떠 있어야 하고(트레이·백그라운드), 설치·권한·끄기 설정이 따라온다. 이는 구조(프로세스 모델)를 바꾸는 결정이다.

## 대안과 버린 이유
- 판정 결과를 `order_replies`에 `late` 칼럼으로 저장: 위 이유로 버렸다. 계산은 가볍다(주문 수천 건에도 목록 판정과 같은 규모).
- Windows 알림: 하루 한 번 앱을 여는 업무 방식에는 과하다. 인터뷰에서 "앱 안에서만"으로 정했다. 실제로 놓치는 일이 반복되면 다시 연다(열린 질문).

## 결과
- 판정 함수는 순수 함수(`src/replies.js`)로 두고 단위 시험으로 규칙을 고정한다(약속일 당일은 늦음이 아님, 새 회신이 약속일 이전 날짜면 해제되지 않음 등 경계를 시험 항목으로).
- DB에는 판정 열이 없다. 다른 기기·복원 뒤에도 같은 기록이면 같은 결과다.
