# ADR-0004: 주문번호와 공급사 이름 글자를 그대로 키로 쓴다

- 날짜: 2026-10-20
- 상태: 결정됨. **가정에 기댄 결정이다** (실제 회사 파일로 확인하지 못했다)

## 결정
- 기록류는 주문번호(글자)로 주문에 붙는다. 주문번호는 **영원히 유일하다고 본다**(사용자의 MRO 경험).
- 공급사 관련 기록은 공급사 이름 글자로 붙는다. 공급사 마스터 테이블을 만들지 않는다.
- 주문의 단위는 주문번호다. 한 주문번호의 품목 줄이 여러 개여도 안내는 주문 하나에 한다.

## 왜 되돌리기 어려운가 / 왜 의외인가
- 이 키가 DB의 모든 기록 행에 박힌다. 나중에 "주문번호가 해마다 겹친다"거나 "공급사 이름이 (주)가온산업과 가온산업으로 갈린다"는 것이 드러나면, 기존 행의 키를 고쳐야 하고 기록이 다른 주문·공급사에 잘못 붙은 채 쌓일 수 있다.
- 주문 원본을 DB에 두지 않으므로 주문번호를 검증할 기준 테이블이 없다.

## 대안과 버린 이유
- (주문번호 + 공급사)·(주문번호 + 발주일) 복합키: 앱의 모든 키와 화면이 바뀐다. 지금은 필요하다는 증거가 없다.
- 공급사 마스터 테이블: 이름 변경·합치기는 쉬워지지만 화면에 공급사 관리라는 새 일이 생긴다.

## 결과
- 실제 파일이 생기면 가장 먼저 확인할 가정으로 `DB_PLAN.md` 위험에 올린다(주문번호 중복, 공급사 표기 흔들림).
- 키 컬럼은 `order_no text`, `supplier_name text`로 두고, 나중에 정규화하기 쉽게 이름을 일관되게 쓴다.
