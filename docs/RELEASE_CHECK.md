## 9.4 여정 워크스루 (스크립트, 패키지된 앱)

대상: 패키지된 앱 납기 알리미.exe

| 여정 | 조작 횟수 | 건당 조작 | 화면 반응 시간(기계) | 순서 |
|---|---|---|---|---|
| CUJ-1 한 건 안내 기록 (마우스) | 2 | 2 | 537ms | 주문 선택 → 안내함으로 기록 |
| CUJ-1 한 건 안내 기록 (키보드만) | 5 | 5 | 1076ms | 표에 포커스 → Enter(상세로) → Tab → Tab → Enter(기록) |
| CUJ-1 한 연구원 건을 한 통으로 (건수 2) | 4 | 2.0 | 1039ms | 연구원 칸 클릭 → 한 통 안내문 열기 → 복사 → N건 안내함으로 기록 |
| CUJ-2 다시 안내 확인 후 기록 | 3 | 3 | 951ms | 기준일 변경(8일 뒤) → 다시 안내 주문 선택 → 안내함으로 기록 |
| CUJ-3 전화 소식 메모 | 4 | 4 | 837ms | 검색 → 주문 선택 → 메모 입력 → Ctrl+Enter로 남기기 |

(CUJ-4는 파일을 여는 대화상자가 자동화되지 않아 E2E S-04가 같은 경로로 확인한다: 열기 1회 + 필요하면 열 연결 확인.)
안내 기록 버튼이 보이려면 더 내려야 하는 양(1280x820 기준, 마지막 연 주문): 0px

해석: 시간은 사람이 읽고 판단하는 시간이 아니라 **화면이 반응하는 기계 시간**이다. 의미 있는 숫자는 조작 횟수다. 한 건 안내 기록은 마우스 2번, 연구원 한 명의 여러 건은 4번에 끝나서 건수가 많을수록 건당 조작이 줄어든다(3건이면 건당 1.3번). 가정 A3("안내 한 건에 10~15분")은 실제 업무로만 확인할 수 있어 이 검증 범위 밖이다.

## 9.7 버그와 알려진 한계

이미 일어난 **S1(치명)·S2(중대) 버그는 0건**이다 (`docs/BACKLOG.md` Phase 7 절). 발견해 고친 것은 대부분 S3·S4와 시험 쪽 문제였다.

알려진 한계 (릴리스 노트와 PRD에 기록):
1. 깨끗한 환경에서 설치·업그레이드·삭제를 직접 해 보지 못했다 (M-10).
2. 스크린리더로 실제 읽히는지 확인하지 못했다.
3. 저장 파일을 암호화하지 않는다. 설치 파일을 서명하지 않았다.
4. 실제 회사 엑셀·이메일·공급사 표로 써 보지 못했다 (가상 데이터만).
5. 안내 기록이 주문당 50건을 넘으면 가장 오래된 것이 조용히 사라진다 (실제로는 거의 닿지 않음).
6. 주문 목록 엑셀은 5,000줄·80열까지만 읽는다 (넘으면 알린다). `.xls`는 열지 않는다.
7. 키를 넣으면(선택 기능) 이메일 추출·열 매핑에서 글이 Claude API로 나간다. 실제 호출은 해 본 적이 없다.
8. 주문을 누르거나 기록할 때 표 전체를 다시 그린다 (10,000행 이상에서 느려짐).
